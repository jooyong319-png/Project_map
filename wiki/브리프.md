# 브리프 — 콕콕콕 (2026-10 재기획)

[[콕콕콕]]의 기준 문서. **판단이 갈리면 이 문서의 원칙으로 결정한다.**
틀은 공용 위키 `C:/Make_Web/wiki/project-planning.md`(체크리스트 정본)를 따른다.

## 한 문장

> **동네만 콕 찍으면, 믿고 따라갈 수 있는 데이트·여행 하루 코스가 나온다.**

## 왜 쓰나 (2026-10-13 결정)

- 처음엔 "블로그 기반 맛집 지도"였지만, 그건 네이버지도·카카오맵·다이닝코드가 이미 한다.
- 진짜 막히는 순간은 **"처음 가는 동네에서 하루 동선 짜기"**다. 블로그 10개를 뒤지고, 동선을 맞추고, 휴무를 확인하느라 1~2시간이 걸린다.
- 무기는 "AI"가 아니라 **"AI가 짠 코스를 그대로 믿고 갈 수 있다"**는 점이다. AI 채팅도 코스를 짜 주지만 아래가 약하다.

| AI 채팅의 약점 | 콕콕콕 |
|---|---|
| 없는 가게·폐업한 곳을 지어냄 | 실존 장소만 후보로 줌 (`api/course.js`, Gemini는 고르기·순서·이유만) |
| 동선·이동시간 엉망, 지도 없음 | 지도 위 번호핀 + 구간 도보/차 시간 |
| 뻔한 관광지·광고성 맛집 | 네이버 블로그 근거(언급 수, 협찬·내돈내산 비율) |
| "이 카페만 바꿔줘"가 불편 | **장소 하나 콕 → 교체, 나머지 동선 유지** ← 핵심 |
| 상대에게 보내기 애매 | 코스 카드 링크 (상대는 설치 없이 봄) |

## 핵심 루프

```
동네 + 분위기 콕 → AI 코스 받기 → 마음에 안 드는 곳 콕 교체 → 상대에게 공유 → 당일 지도 보며 따라가기
```

## 설계 원칙

1. **실존만** — 코스의 모든 장소는 우리가 수집·분석한 실재 장소. AI가 장소를 만들지 않는다.
2. **비용 0에 수렴** — 구글 Places 끔(`GOOGLE_ENABLED`, 1,000건당 $35). 장소=카카오, 근거=네이버 블로그(무료). 분석 결과는 **정적 JSON**(DB 불필요). AI는 사용자가 새로 짤 때만.
3. **생성은 자동, 발행은 수동** — 미리 만든 코스 페이지는 AI가 만들고 사람이 검수해 발행.
4. **가짜 참여 데이터 금지** — 블로그 수는 실제 외부 데이터만. 평점·후기를 지어내지 않는다.
5. **가게에 불리한 낙인 금지** — "광고 많은 집" 대신 "내돈내산 비율 높은 집"처럼 긍정 쪽으로 표현.

## 가장 위험한 가정

> "AI가 짠 코스를, 내가 직접 블로그 뒤져 짠 것만큼 괜찮다고 느낀다."

- 검증: ① 사장님 실전 데이트(성수) → ② 동네 5곳 코스를 지인 커플 10~20쌍에게 "이대로 갈래?"
- 기간: 1주 이내. **검증 전엔 UI를 다듬지 않는다.**

## 알려진 큰 구멍

- **영업시간·휴무 정보 없음** — 구글을 빼면서 사라짐. 카카오 로컬 API는 영업시간을 안 준다. 쉬는 가게가 코스에 들어가면 치명적 → 1단계에서 대안 조사. 임시: "출발 전 카카오맵에서 영업시간 확인" 링크.
- **약관 (2026-10-13 확인) — 지금 설계로는 막힘. 결정 대기.** ↓ 아래 "약관 확인 결과"

## 약관 확인 결과 (2026-10-13)

**네이버 검색 API** — 개발자센터 이용약관 원문, 개별 특약 「2. 네이버 검색 API 서비스」(2026-09-07 시행)에서 직접 확인. 금지:
- 검색 데이터(**가공·파생물 포함**)의 복사·저장·캐싱 — 예외는 기기 24시간 / 서버 이력조회 최대 21일
- 데이터를 **AI에 입력**하거나 학습·개선·평가·노출에 활용
- 검색결과가 표시되는 페이지에 **광고**, 기타 검색 API로 **수익**을 얻는 행위

→ 블로그 수·태그를 저장해 두고(seed), Gemini 후보에 `blog`를 넣고, 광고를 붙이는 구조 전부 해당. **이미 배포된 기존 기능도 해당**.

**카카오 로컬 API** — 데브톡 카카오 답변(2026-10-01, 10-08): 저장 가능한 것은 **장소 ID와 place_url뿐**. 이름·좌표·주소 등은 실시간 호출로만. 결과 전체를 DB/캐시에 저장 불가.

→ "동네 20곳을 미리 분석해 정적 JSON으로" 계획은 카카오·네이버 데이터로는 불가. 저장 가능한 데이터 기반(공공데이터)으로 바꿔야 함.

## 🧪 실험 ① 체크리스트 — 사장님 실전 데이트

**출발 전 (코스 받을 때)**
- [ ] 코스 받는 데 몇 초? 결과를 보고 첫인상이 "오 괜찮네"인가 "음…"인가
- [ ] 내가 블로그 뒤져서 짰다면 넣었을 곳이 몇 개나 들어 있나
- [ ] 바꾸고 싶은 곳이 몇 개? 왜? (→ 교체 기능의 우선순위 근거)
- [ ] 여자친구에게 보냈을 때 반응 (스크린샷이라도)

**당일 (따라가면서)**
- [ ] 쉬는 날·브레이크타임에 걸린 곳이 있었나 ← 영업시간 구멍의 실제 크기
- [ ] 표시된 도보 시간이 실제와 맞았나
- [ ] 순서가 자연스러웠나 (점심 → 구경 → 카페 → 저녁)
- [ ] 줄 서느라 일정이 밀렸나
- [ ] 중간에 앱을 다시 열었나? 열었다면 뭘 하려고?

**다녀와서**
- [ ] 다음에 다른 동네 갈 때 또 쓰겠나? 안 쓴다면 이유 한 줄
- [ ] 여자친구 한 줄 평
